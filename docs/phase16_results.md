# Phase 16 results — Tamil / English multilingual support

Date: **2026-08-17**.

This phase adds English ↔ Tamil presentation for the citizen portal and the on-demand PDF report. The model was not retrained. `citizens.csv`, `eligibility_dataset.csv`, and `decision_tree.joblib` were not modified. Eligibility rules, hybrid ranking, JWT authentication, wallet schema, and recommendation history schema were not changed.

## What changed

- Centralized frontend dictionaries in `frontend/src/i18n/` with a header switcher: `English | தமிழ்`.
- The selected language is stored in `localStorage` under `schemewise.language` and restored after refresh.
- User-facing UI copy, validation, empty states, wallet/history/comparison chrome, and dynamic counts are translated.
- `POST /api/v1/reports/recommendations` accepts optional `language: "en" | "ta"` and remains backward compatible when the field is omitted.
- Tamil PDFs embed a Unicode Tamil font: Noto Sans Tamil when `backend/app/assets/fonts/NotoSansTamil-Regular.ttf` is present, otherwise Windows **Nirmala UI** from `Nirmala.ttc`. Eligibility calculations are unchanged.

## Intentionally untranslated

Scheme IDs, official catalog names/URLs, API field names, stored wallet codes, model names, `CORE` / `ADVANCED` / `HOLD`, backend rule reasons, and API-supplied evaluation notes.

## Testing

- Frontend `npm test`: 66 passed, including existing English assertions and new language-switcher tests.
- Frontend `npm run build`: succeeded.
- Backend PDF service tests: English report still contains the project title metadata and Times fonts; Tamil report is a valid PDF, embeds a TrueType Tamil face (Nirmala UI or Noto Sans Tamil), and does not use Times-Bold.

## Limitations

Tamil scheme names are not invented. Rule-reason sentences remain English because they are generated by the existing rule engine. A Tamil PDF on a non-Windows machine needs `NotoSansTamil-Regular.ttf` in `backend/app/assets/fonts/`.
